# mysearch 精度手册：怎么过滤、怎么打分、怎么证明

- 日期：2026-10-24
- 状态：已实现并实测（M0+）
- 实测脚本：`node probe/eval.mjs`（9 条中英查询，标注=标题含期望关键词）

---

## 0. 一句话

**精度靠"闸门 + 过滤链 + 概念匹配"三层硬规则，不靠调分数。** 分数只负责在合格集合里排序；不合格的条目根本进不了打分。

---

## 1. 先定义"准确"

搜索结果不准确，只有四种真实病因，对应四种治法：

| 病因 | 典型症状（实测见过） | 治法 |
| --- | --- | --- |
| 引擎答非所问 | 查"大模型 推理 优化"，Bing 返回"大（汉语文字）_百度百科" | 引擎级相关性闸门（top3 零概念命中 → degraded） |
| 结果不是文档 | "xxx的最新相关消息"聚合页、"360翻译"onebox、文库预览 | 过滤链：聚合页标题 / 噪声域名 |
| 结果不是答案 | "中国政府网"首页、"NVIDIA 官网"、"TOKIO - 知乎" | 过滤链：门户首页 / 实体页 / 标题无概念 |
| 概念只沾一个词 | 查"tokio select 用法"，返回只含 tokio 的页面 | 概念分组匹配（必须命中多数概念） |

> 关键认知：**"分数调低一点"解决不了这四类问题**。前两类是"该不该进来"，后两类是"够不够格"。所以过滤器必须在打分之前。

---

## 2. 概念匹配（替代 bigram 计数）

早期实现把中文拆成 2-gram 统计覆盖率，结果"大模型 推理 优化"和"大（汉语文字）"能沾上一个"大"字就混过去。现在改成**概念组**：

```
查询 → 按空白/标点切组 → 去掉无信号词（用法/教程/怎么/如何…）
     → 去掉修饰前缀（最新/官方/热门…："最新政策"→"政策"）
     → 得到 concepts = ["tokio", "select"]
```

命中规则：

| 组数 | 必须命中 |
| --- | --- |
| 1 | 1 |
| 2 | **2**（两个概念都得在，否则"中国政府网"首页也能过） |
| 3–4 | 2 |
| 5+ | ⌈n/2⌉ |

匹配判定：
- ASCII 组：先做**整词**匹配（"ai" 不会命中 "said"），长度 ≥4 才允许子串（"vllm" 命中 "vllm-project"）。
- 中文组：先整串包含；不中则按 **2-gram 覆盖率 ≥ 0.6**（"推理优化" vs "推理 与 优化"这类断词）。

---

## 3. 过滤链（严格顺序，每条都记账）

```
noise_host        已知噪声域名（fanyi.so.com / wenku.so.com / zhidao.baidu.com / so.com 包装链接）
aggregator_title  标题是聚合页（"的最新相关消息"/"相关搜索"/"搜索结果"/"文库"…）
portal_root       站点首页且未覆盖全部概念（"nvidia 财报 2026" → 官网首页）
low_match         命中概念数 < 要求（"大（汉语文字）"命中 0）
title_mismatch    概念只出现在摘要、标题一个都没有（"财务报告"）
entity_page       多概念查询下，标题只是"品牌 + 站点后缀"（"TOKIO - 知乎"）
script_mismatch   中文查询命中纯英文页
dup_content       摘要去标点后前 40 字相同（同一内容换域名）
```

设计取舍三条：

1. **宁可少一条，不要错一条**——所以过滤是硬删，不是降权。分数只用于排序。
2. **每一步都可解释**——`metadata.filters` 直接回传每条原因被删了几条，见下面实测。
3. **全删空时降级，而不是返回噪声**：若严格链把结果删空，退回到"至少命中 1 个概念且不是噪声域名"的集合，仍不拿聚合页凑数。

---

## 4. 打分：只在合格集合里排序

`score = Σ wᵢ·fᵢ / Σ|wᵢ|`，权重可为负（惩罚），六特征：

| 特征 | 权重 | 作用 |
| --- | --- | --- |
| `rrf` | 1.0 | 跨源名次融合（新源零校准即可加入） |
| `coverage` | 0.8 | 查询概念在标题+摘要的覆盖比例 |
| `title_coverage` | 0.5 | 同上，只看标题 |
| `phrase` | 0.4 | 整句相邻命中（"大模型推理优化"连写） |
| `authority` | 0.3 | 权威域名（gov.cn/edu.cn/github.com/docs.rs/arxiv.org…） |
| `length` | −0.1 | 摘要过短或过长扣分 |

排序键：`score desc → 源内名次 asc → url asc`，完全确定性、可复现；`explain:true` 返回每个特征的贡献。

## 5. 实测：改动前后（同一套 9 条查询、同一标注）

| 指标 | 过滤前 | 过滤后 |
| --- | --- | --- |
| 返回条目的准确率（precision） | 0.79（34/43） | **1.00（35/35）** |
| 平均返回条数 | 4.8 / 5 | 3.9 / 5 |
| 单查询延迟 | 390–900ms | 190–760ms |

过滤前后每条查询的删除原因（`metadata.filters` 实测样本）：

```
大模型 推理 优化      aggregator_title=1 low_match=5 noise_host=2   → 返回 2 条
vLLM 显存 优化        low_match=3 portal_root=2                     → 返回 4 条
tokio select 用法     entity_page=1 low_match=3 portal_root=2       → 返回 4 条
贵州茅台 2025 年报    title_mismatch=2 noise_host=2 low_match=2     → 返回 4 条
nvidia 财报 2026     low_match=3 portal_root=2 noise_host=1         → 返回 4 条
中国政府网 最新政策    entity_page=1 low_match=3 portal_root=1       → 返回 3 条
```

---

## 6. 代价：召回下降，这是刻意的

现在**只有 2 个引擎**，删掉噪声后经常凑不满 5 条（平均 3.9）。这是"准确优先"的必然结果，不是 bug。补召回的正确做法不是放宽过滤，而是**加合格供给**：

1. **M1 声明式渠道**：把 IT之家 / 新浪 / arXiv / Crossref / GitHub / StackExchange / 政府网接进来（都是配置，不改代码），同一查询的合格候选翻倍。
2. **tier_c 兜底**：tier_a/b 去重后不足 `max_results×0.5` 时，再打第 3 个源（仍受"单请求 ≤4 上游"约束）。
3. **聚合页下钻**：对"xxx的最新相关消息"这类页面，抓其内部条目而不是整体丢弃（需要额外一次请求，放进 tier_c 预算里）。
4. **英文技术查询**：用 GitHub/HN/StackExchange 直接补，别指望中文引擎。

## 7. 已知误删（要盯着的边界）

| 场景 | 现象 | 缓解 |
| --- | --- | --- |
| 标题不含关键词但正文高度相关 | "中华人民共和国劳动合同法" 对"劳动法 试用期"被判 `title_mismatch` | 可对 `title_mismatch` 放宽为"标题或摘要命中 ≥1 且摘要覆盖 ≥0.5"，用 eval 验证净收益 |
| 极短标题 | "财务报告" 这类容器页 | 已按 `title_mismatch` 删；若确为官方年报入口，后续可加"域名+路径白名单" |
| 单概念查询 | "nvidia" 只命中 1 个概念，首页可过 | 单概念查询不做 `portal_root` 拦截（首页就是答案） |

调参纪律：**任何阈值改动都要跑 `probe/eval.mjs` 给前后数字**，不接受"感觉准了"。

## 8. 下一步（精度相关）

1. 评测集扩到 40+ 条并加"必须排在 top3"的强标注，用 `precision@3` 替代现在的 top5 粗标注。
2. 过滤链加 `stale`（查询含时间词、摘要日期过旧）与 `login_wall`（"登录后查看"）。
3. 聚合页下钻（见 §6.3），这是"高精度 + 高召回"唯一能同时成立的路。
4. 打分权重用 `eval --grid` 搜一轮，把 `authority`/`phrase` 的权重从手调改成数据定。
